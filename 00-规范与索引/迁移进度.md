## 四、文档元数据（front-matter）

39 篇 md 全部在文首加了 YAML 块，字段约定：

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `title` | 是 | 中文标题 | 与文件名一致或更完整 |
| `board` | 是 | `[鲁班猫4]`、`[鲁班猫4, 鲁班猫5]`、`[鲁班猫]` | 通用则写 `[鲁班猫]` |
| `soc` | 视情况 | `RK3588S`、`RK3576`、`RK3568` | 文档明确时才写 |
| `kernel` | 视情况 | `6.1.99`、`5.10.160`、`"6.1"` | 纯数字带点时加引号，防 YAML 解析成浮点 |
| `os` | 视情况 | `Ubuntu 22.04`、`Debian 12`、`Kali Linux` | 多系统用 `[Debian 12, Ubuntu 22.04]` |
| `tags` | 是 | 2~4 个 | 取功能域 + 技术点，用于检索 |
| `updated` | 是 | `YYYY-MM-DD` | 最后**内容**修改日期（迁移与加元数据不算） |
| `formats` | 是 | `[md]` 或 `[md, pdf]` | 标出是否已有 pdf 成品 |

示例：

```yaml
---
title: imx415 4K60fps 驱动移植
board: [鲁班猫4]
soc: RK3588S
kernel: 5.10.160
tags: [摄像头, sensor, 设备树, ISP]
updated: 2026-08-12
formats: [md]
---
```

有了统一字段后，README 索引表可以由脚本扫描 front-matter 生成，新增文档时不必手工改 README。

## 五、回滚方式

迁移全部通过 `git mv` / 文件改名完成，重命名被 Git 识别为 rename，历史可追溯。
需要回退到迁移前状态：`git reset --hard <迁移前的提交>`（迁移提交为 `chore: reorganize docs by function domain`）。

## 六、维护脚本

两个脚本都刻意写成**纯 ASCII**——Windows PowerShell 5.1 按 ANSI 读 `.ps1`，脚本里一旦出现中文、甚至只是一个 `—` 破折号，引号就会因乱码错位而报「字符串缺少终止符」。中文只允许出现在数据文件或文档 front-matter 里：

| 文件 | 内容 |
|---|---|
| `index-labels.tsv` | 索引表的表头与占位符文案（`key=value`，UTF-8），脚本运行时读取 |
| 各文档 front-matter | `title` / `summary` / `board` 等实际内容 |

`gen-index.ps1` 开头有自检：读自身字节，发现 >127 的字节就告警，避免再次踩坑。

| 脚本 | 作用 | 用法 |
|---|---|---|
| `gen-index.ps1` | 扫描所有 md 的 front-matter，重写 README 中 `INDEX` 标记之间的索引表 | `... -File "00-规范与索引\gen-index.ps1"`，加 `-Check` 只体检不写文件 |
| `slim-repo.ps1` | 重打包 `.git`，可选重写历史删掉大文件 | `-Repack` 安全；`-PurgeHistory -Yes` 会改提交号 |

`gen-index.ps1` 的取舍规则：同一主题按 **md > pdf > docx** 只留一行（md 行用 `formats` 字段标注是否另有 pdf；docx 与 pdf 同名时只列 pdf）；没有 md 的 pdf/docx 单独成行，元数据列显示 `—`。缺 `summary` 或没有 front-matter 的文件会在输出里告警。
